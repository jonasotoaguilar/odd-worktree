# Code Map

The question this page answers: which file owns a responsibility before you open code?

| Path | Responsibility |
| --- | --- |
| `extensions/odd-worktree-tools.ts` | The **only** Pi entry point. Plain JavaScript under a `.ts` name (`// @ts-nocheck`), so the test copy-to-`.mjs` loader works. Behind the bridge gate it registers the four commands (`/issues` only where the local `gh` probe finds the CLI), the two tools, the `worktree-warp` message renderer, the file card through the host's `registerToolRenderer`, the `GITHUB` rail section (also `gh` only) and the `ODD` rail section (scoped to the session's registered worktrees, so it survives `Worktrees+` Off), the one `activity` design (one `Card activity` line over `bash`, the three read-only shell tools and `read`, `write` and `edit`, the last two scoped to skill and ODD paths, which the file cards ask about too — no switch of its own) and the one `color` design (one `Card diff` line over `write` and `edit`, whose seam is warmed only after the bridge accepted the registration), the file picker's `alt+p` shortcut bound directly on the host (`GENTLE_PI_FILES_KEY` overrides it) and the issues panel's `alt+i` beside it (`GENTLE_PI_ISSUES_KEY` overrides it, and it is bound only where the `gh` probe registered `/issues`), and the `session_start` / `session_shutdown` / `turn_end` / `tool_call` / `tool_result` / `before_agent_start` hooks. The issues `gh` gate is DISPATCHED startup work, never an awaited step of `session_start`: no child process and no network call sits on a session start or a session switch, a late answer is dropped by the generation the dispatch captured, and outside a repository the gate settles on a state instead of retrying. Without the `gh` CLI the two issues surfaces are never registered at all, so no gate runs and nothing is drawn, announced or refused. Registration is DEFERRED behind gentle-shell-bridge: with the bridge absent it registers nothing but the one observer the missing-bridge notice needs, and the surface lands once, the moment the bridge is published or announced. |
| `lib/modules.js` | The two module switches (`Codegraph+`, `Worktrees+`): the persisted document in the bridge's store, ON unless exactly `false`, and the `Tools` page rows with their one restart notice. The extension reads it once, when it registers, and leaves each half out when it is off. |
| `lib/worktree-git.js` | The git seam: identity, worktree listing, branch validation, the canonical target path `<repo-parent>/<repo-name>-worktrees/<slug>` and its helpers, and the async argv runner. |
| `lib/worktree-registry.js` | The one ownership rule, with no file: a checkout this package created is a directory under `<repo-parent>/<repo-name>-worktrees`, so the path decides. Partitions Git's listing into ours and outside, and parses `git worktree list --porcelain` for the create path. |
| `lib/worktree-create.js` | `worktree_create`'s core: request validation, base resolution, the ODD-named destination, the refusals sentence for sentence, plan execution and the fixed output lines. |
| `lib/worktree-list.js` | `worktree_list`'s rendering: rows, order, detail lines and footers, from one structured row list. It writes nothing. |
| `lib/worktree-guard.js` | The tool guards' decisions: `decideBashGuard` over the command text, `decideWriteGuard` over the paths of an `edit`/`write`, both pure over injected seams; they spawn nothing and read no file content. |
| `lib/skill-read-guard.js` | The skill-read `bash` guard's decision: a pure function over the command text that refuses a reader (`cat`, `sed -n`, `head`, …) pointed at a skill file and names the `read` tool instead. |
| `lib/artifact-read-full.js` | The whole-read rule of a skill's or an ODD's Markdown: a `read` of a `.md` below a `skills/` or an `odd/` folder has its `offset` and `limit` deleted from the host's own `event.input`, so the call delivers the whole document. Pure, never throws, blocks nothing; the extension registers it under `Worktrees+`. |
| `lib/worktree-hooks.js` | The preparation chain of a create: submodules, local inputs, `copy_changes`, build-cache and asset links, the setup slot, and the clone-local `gentle-ai/worktree-hooks.json` that extends the lists. |
| `lib/worktree-setup.js` | The setup chain: the closed command table one lockfile selects, the plan, and the two notice sentences. |
| `lib/worktree-setup-runner.js` | The tracked background task of a create: runs the planned commands one child at a time, sends their output to its own log under the system temp directory, and reports one notice built from the child process outcome. No state is persisted. |
| `lib/worktree-remove.js` | Git-only removal: `git worktree remove <absolute path>`, branch kept. |
| `lib/worktree-symlinks.js` | Symlink policy for a checkout. |
| `lib/worktree-changes.js` | Pending-change snapshot and transfer (the panel's `changes` selection, and a typed warp's copy). |
| `lib/worktree-session-guard.js` | The active-session guard the panel's `ctrl+d` runs, with the caveats it discloses. |
| `lib/worktree-warp-busy.js` | This session's busy evidence for a warp: the in-flight tool counter, agent-task counters, its `job_list` jobs, the one pending handoff, and the persistent row that handoff shows. |
| `lib/worktree-warp-sessions.js` | Warp/fork bookkeeping in the session files the host owns. |
| `lib/checkout-facts.js` | The facts one checkout row shows in the selector. |
| `lib/worktree-card.js` | The `worktree-warp` message renderer (the moved/queued card), composed on the card substrate like the tool cards. |
| `lib/card-style.js` | The one style reader: the live process-wide slot Gentle Shell publishes, then the strict `<home>/card-style.json`, then `float`. It reports the source and the reason it fell back, caches only the document branch, and is re-read on `session_start`. |
| `lib/card-content.js` | The one reader of the card content level Gentle Shell publishes (`default` or `minimal`), read at paint time; `/warp`, the CodeGraph card and the file cards honor it, while the two worktree tool cards keep their three info rows in both levels (S2). |
| `lib/bash-activity.js` | The classifier the bash card heads with: the one quote-aware segmenter, the eight named families and the mark and theme role each wears, the precedence between them, and the package's own conservatism — a segment it cannot name leaves the call unnamed, which is what the generic `$ bash` heading is. |
| `lib/bash-inline-script.js` | What an inline interpreter script proves from its own text (`python3 -c`, `node -e`, `python3 - <<'PY'`): a deletion, a write, or read-only use of a short list of standard modules; anything else is unread. |
| `lib/bash-destructive.js` | The destructive family's evidence: the segment that names a deleting program, and the whole command whose pipe or heredoc feeds a database client its statements. Evidence only — no permission, guard or execution decision may read it. |
| `lib/bash-frame.js` | The bash card's frame and closing rule as pure row functions: repaint every frame cell in one theme role, and write a finished call's duration into the closing rule (neon and float), keeping every row's width. |
| `lib/bash-design.js` | The `activity` design: a `registerToolDesign` registration on gentle-shell-bridge whose `apply` swaps the host's `$` heading mark for the family the classifier names (from `ctx.render.args` when the bridge provides it, else only when the heading provably shows the whole command; `$ bash` when nothing names it), heads every `grep`/`find`/`ls` card `⌕ exploring`, paints the label and frame in theme roles and adds the duration. `read`, `write` and `edit` are declared on the line for coverage alone — the bridge's answer is what lets the file card ask about them — so the design paints nothing for any of the three. One registration only, shaped BEFORE it is made: one `Card activity` line over `[bash, grep, find, ls, read, write]` on a bridge at 0.6.0 or later, which gains `edit` and a scope on `write` and `edit` limited to skill and ODD paths at 0.9.0 or later, the single `tool: "bash"` design on anything older, and a release string it cannot read at all is asked with a throwaway capability probe. A release whose digits equal a cutoff but carry a prerelease or build suffix never meets it. `apply` is pure; the bridge owns the renderer, the line and its persistence, and the module only seeds `activity` once and carries a valid value stored on its old `tools` line key over to `tags`, both before it registers. |
| `lib/diff-design.js` | The `color` design: the second registration, on the bridge's own `Card diff` line over `write` and `edit`, asked unchanged for a call whose path the file card claims. It draws a write as an IDE pane inside the host's own frame — line-number gutter, the body in the host's highlighter's roles, the host's collapsed budget and fold row — and an edit's diff recoloured into `toolDiffAdded`/`toolDiffRemoved`/`muted`, every row measured as plain text before it is painted and every colour a theme role. Onto the bridge it writes only the first-run seed of `color`; the seam it paints through is the same `filesAgentSeam` `/files` uses. Registers nothing on a bridge older than 0.9.0 (no per-(`line`, `tool`) claim) or on the prerelease/build of that cutoff, and caches nothing: the highlighter resolves the live theme per call. |
| `lib/jobs-card.js`, `lib/jobs-card-resolver.js` | The jobs card: the resolver that claims `bash_background`, `monitor`, `job_stop` and `job_list`, which have no renderer of their own, and their call/result slots on the card substrate. The gate is strict and read when the card is built — only `api.resolveToolDesignSelection(tool)` answering `design` with `odd-worktree.bash-activity` paints; every other answer, and no answer, hands back what the chain resolved. It shares its drawing helpers with the file cards (`lib/file-card.js`) and its gate reader (`bridgeApi`, `ACTIVITY_DESIGN_ID` in `lib/file-card-resolver.js`). |
| `lib/message-card.js` | The two advisory message cards: `gentle-pi.exploration-budget` (`⌕ Exploration budget`, `info`) and `gentle-pi.verifier-settle-reminder` (`⚑ Verifier reminder`, `warning`) registered as gentle-shell-bridge message designs, one ungrouped design per custom type, with the numbers the message states as the heading's detail. Each design FOLLOWS the tool switch this package already owns — `follows: { line: TOOLS_LINE, id: BASH_DESIGN_ID }` from `lib/bash-design.js` — so `Card activity` answering `activity` paints them, resolved by the bridge on every pass and read from the tool document, never written: no switch of its own, no row in the menu, no seed. It draws through the card substrate (`lib/shell-card.js`) with the whole body at any content level and the bridge's `[customType]`/blank plain-body decoration dropped, and it reads the host's style on every paint, never `ctx.cardStyle`. It registers NOTHING unless the bridge's published release is a clean numeric release of at least 0.12.1 (any prerelease, build, trailing text or four-part string is unreadable), an inactive claim then costing a registry walk and at most one tool-document read — 0.12.0 has `follows` but let a stored message id veto it, so the follow promise needs 0.12.1 — and 0.12.0, anything below the cutoff, a prerelease or build suffix of it, and an unreadable string all fail closed, because a bridge that ignores `follows` while accepting the registration would mint a `Message <type>` switch. There is no capability probe — one cannot tell a refusal for an unrelated reason from a validated `follows`, and an accepted-then-withdrawn probe can leave the bridge's row provider installed. |
| `lib/file-card.js`, `lib/file-card-resolver.js`, `lib/skill-odd-card.js`, `lib/file-card-markdown.js` | The file cards: the resolver that claims `read`, `edit` and `write` and its call/result slots; the bridge gate inside the resolver — `api.resolveToolDesignSelection(tool, args)` asked per paint with the call's own args, because the line's claim on `write` and `edit` is a scope, painted only for `odd-worktree.bash-activity`, pre-switch behaviour when the reader is absent; the path's identity rule and the heading's roles; and the document body — a read's text, a write's content, an edit's resulting fragment (`editedFragment`), never an edit's diff — through Pi's `Markdown` in the theme's Markdown roles, placed without re-painting (invariant 23); a call that leaves no fragment (a pure deletion, a failed call, a non-Markdown path) keeps the rows it has. |

A failed refresh keeps the rows and marks them `stale`; a cwd outside a repository is one short `dim` line (`not a git repository`, never `error`), and so is a checkout that is a repository with no remote (`not a GitHub repository`, gh's no-remote refusal drawn as a state); either keeps no timer. A missing `gh` CLI never reaches this section — the extension does not mount it without the CLI — so the one `dim` `gh CLI not installed` line is only the fail-closed answer for a `gh` that vanished after load. It schedules refreshes and never waits on a child process; only a bridge that published its API can show it. |

| `lib/related-issues-cache.js` | The IN-MEMORY half of the issues read cache: the three scoped views (`mine`, `assigned`, `involved`) that one combined read answers, keyed by repository identity, with the 100-then-20 read plan, the merge by issue number, the count invariant that forces a full re-read, and the ten-minute bound measured from the last FULL read, so a stream of deltas cannot postpone it. | `lib/issues-cache-store.js` | The DISK half of that cache: ONE versioned document under `$XDG_CACHE_HOME/odd-worktree/` (else `~/.cache/odd-worktree/`), one entry per repository identity keyed exactly as the in-memory cache keys its own, bounded to the eight most recent identities and written as a temp file plus a rename. `package.json` ships `extensions`, `lib`, `tools` and `README.md`, and declares
`pi.extensions: ["./extensions/odd-worktree-tools.ts"]`. There are no runtime
`dependencies`; the three `@earendil-works/*` packages are peer dependencies the
host provides.
